# 威胁模型

> 本文档的价值在于**明确不防什么**。任何安全声明都不得超出本文范围。

## 1. 资产

| 资产 | 敏感度 | 说明 |
|---|---|---|
| 消息明文 | 高 | 通信内容 |
| 身份私钥（IK） | 极高 | 泄露 → 可被冒充；M1 下还会导致历史消息全解 |
| 会话密钥（SK） | 极高 | 泄露 → 当前轮消息可解 |
| 联系人与通信关系 | 中 | 社交图 |
| 通信元数据（时间/大小/频率） | 中 | 可推断行为模式 |
| 本地消息库 | 高 | 历史记录 |

---

## 2. 攻击者模型

### 2.1 在范围内的攻击者

| 编号 | 能力 | 典型场景 |
|---|---|---|
| **A1** | 被动嗅探局域网流量 | 同一 WiFi 上的其他设备、被入侵的路由器 |
| **A2** | 主动中间人（可篡改/注入/重放包） | ARP 欺骗、恶意 AP |
| **A3** | 伪造 mDNS 广播 | 广播他人指纹诱导连接 |
| **A4** | 发送畸形/超大帧 | DoS、内存耗尽 |
| **A5** | 重放历史密文 | 重放攻击 |
| **A6** | 窃取离线数据库文件 | 设备失窃、备份泄露 |
| **A7** | 暴力破解口令 | 弱口令场景 |
| **A8** | 恶意中继节点（公网阶段） | 转发流量、观察元数据；**无法解密内容** |
| **A9** | 恶意信令/会合服务器（公网阶段） | 观察社交图、注入伪造候选地址、拒绝服务 |
| **A10** | 发送恶意文件（附件） | 木马、利用接收方的解析漏洞 |
| **A11** | 磁盘耗尽（附件） | 用超大文件撑满接收方磁盘 |

### 2.2 不在范围内的攻击者

| 编号 | 能力 | 说明 |
|---|---|---|
| **B1** | 控制通信端点设备（恶意软件、被入侵系统） | E2EE 无法防御端点妥协 |
| **B2** | 物理接触 + 内存取证 | §4.5 已说明 Go 无法保证清零 |
| **B3** | 全局流量分析（ISP 级） | 元数据不加密 |
| **B4** | 供应链攻击 | 编译器/依赖被污染 |
| **B5** | 侧信道（功耗、时序） | 未做防护 |
| **B6** | 胁迫用户交出密钥 | 无 duress 模式 |

## 3. 防护矩阵

| 威胁 | 防护 | 效果 |
|---|---|---|
| A1 被动嗅探 | 应用层 AEAD 加密 | ✅ 内容不可读；元数据可见 |
| A2 主动 MITM（无带外验证） | ⚠️ **仅 TOFU** | ❌ 首次交换公钥时可被替换 |
| A2 主动 MITM（已带外验证） | 指纹绑定 + 签名认证 | ✅ 可检测 |
| A3 伪造 mDNS | 连接后校验握手指纹 | ✅ 发现不一致即断开 |
| A4 畸形/超大帧 | `MaxFrame` 校验、fuzz 测试、连接限流 | ✅ |
| A4 连接耗尽 | 未识别连接数上限 + 握手超时 | ✅ |
| A5 重放 | nonce + seq 滑动窗口 + 时间戳窗口 + sid 去重 | ✅ 窗口内重复可检测 |
| A6 数据库泄露 | 明文正文不落库，本地密钥加密 | ⚠️ 依赖口令强度 |
| A7 口令暴力破解 | argon2id（m=64MiB, t=3） | ⚠️ 强口令有效，弱口令无效 |
| A8 恶意中继 | 应用层 E2EE 独立于传输层 | ✅ 内容有保护；**元数据无保护** |
| A9 信令服务器被控 | 信令消息用**身份密钥签名**；应用层指纹验证兜底 | ✅ 无法 MITM；仍可 DoS |
| A10 恶意文件 | 不做扫描；不按 MIME 自动打开；打开交给操作系统 | ❌ 内容风险由用户承担 |
| A11 磁盘耗尽 | 接收前检查可用空间 + 大小上限 + 配额 | ✅ |
| 篡改消息 | AEAD tag + AAD | ✅ |
| 会话密钥泄露 | 定期 ratchet（M2） | ⚠️ 影响窗口 ≤1 轮 |
| 附件重排 | `index` 进 nonce 与 AAD | ✅ |
| 附件截断 | `total_chunks` + 末块 `is_final` 标志 + `file_hash` | ✅ |
| 附件块重放 | 接收方位图去重 + 会话级重放窗口 | ✅ |
| 附件文件名泄露 | 传输在 SECURE 帧内自动加密；本地用 MK 加密 | ✅ |
| 路径穿越（附件） | 存盘路径用 `file_id`，原始文件名仅用于显示 | ✅ |

### 3.1 关于 A8 的诚实说明

中继**看不到消息内容**（应用层 E2EE，见 [nat-traversal.md](nat-traversal.md) §10.1），但它能看到：

- **谁在和谁通信**（社交图）；
- 通信的时间、持续时间、频率；
- 流量大小（近似等于消息与附件的大小）。

这是**元数据泄露，不是内容泄露**。不要把"E2EE"表述为"中继什么都看不到"。

## 4. 关键风险与诚实结论

### 4.1 首次交换公钥的窗口（最大弱点）

```
用户 A 添加 B 的公钥
   ↓
若通过不安全渠道获取（聊天软件截图、邮件、粘贴板）
   ↓
攻击者可能已完成替换 → A 实际上在和攻击者通信
   ↓
防御：带外比对指纹（扫码 / 当面 / 可信渠道）
```

**这是任何基于公钥的 E2EE 方案都无法用密码学单独解决的问题**，必须靠用户行动。因此：

- UI 必须**持续**标示未验证状态（[ui-gio.md](ui-gio.md) §4.4）；
- 不得在文案中暗示"已加密 = 安全"。

### 4.2 M1 无前向保密

若实现选择 M1（见 [crypto-protocol.md](crypto-protocol.md) §5.3、§9.3）：

> **身份私钥泄露 ⇒ 全部历史消息可解密。**

因此 M1 下：
- UI **禁止**出现"前向保密""向前保密""forward secrecy"等字样；
- 如果生产环境使用 M1，需在隐私说明中明确告知用户这一性质。

### 4.3 元数据不加密

| 暴露给谁 | 能看到什么 |
|---|---|
| 局域网嗅探者 | 两个 IP 在通信；帧数量与时间；消息的密文长度（≈明文长度） |
| mDNS 观察者 | 设备名、指纹（即使指纹不可信，也暴露身份意图）、在线状态 |
| 未来中继 | 上述全部，外加连接持续时间 |

**消息长度 ≈ 明文长度**这一点尤其值得注意：可通过密文长度推断消息内容类型（如"是/否"、"好的" vs 长段落），甚至对固定模板消息做字典攻击式的长度指纹。

**缓解手段（首期不做，但需在文档中声明）**：
- 固定长度填充（牺牲带宽）；
- 随机延迟发送（牺牲实时性）；
- 常量速率信道（牺牲带宽巨大）。

**首期结论：接受该风险，并在隐私说明中如实告知。**

### 4.4 端点安全不在范围内

若任一端设备被入侵：
- 攻击者可读取内存中的密钥与明文；
- 可截取键盘输入；
- 可篡改 UI 显示（让用户以为验证通过）；
- 可冒充用户发送消息。

**这超出 E2EE 的能力范围。** 不要向用户暗示"用了 KeyTalk 就绝对安全"。

### 4.5 内存清零不可靠

如 [crypto-protocol.md](crypto-protocol.md) §10.5 所述，Go 的 GC 与编译器优化使得密钥材料**无法保证**从内存中彻底清除。因此本方案**不声称**抗内存取证。

### 4.6 无抗胁迫设计

没有"隐藏会话""假密码""暗号报警"等 duress 功能。若用户被胁迫解锁，所有数据都会暴露。

### 4.7 公网阶段的元数据暴露面扩大

局域网阶段，元数据只暴露给同一广播域；引入会合服务器与中继后，**暴露面显著扩大**：

| 暴露对象 | 能看到什么 | 是否可避免 |
|---|---|---|
| 会合/信令服务器 | **谁在找谁**（社交图）、在线状态、候选地址（IP） | 需匿名会合 / onion 路由，**超出范围** |
| TURN / 中继 | 通信双方 IP、时长、流量大小 | 同上 |
| 上述二者的日志留存 | 长期行为画像 | 需无日志策略或自建 |

**这意味着**：公网阶段虽然内容仍受 E2EE 保护，但**"谁和谁在通信"这一事实会暴露给基础设施运营方**——即使是自建服务器，也暴露给运营者。这必须向用户如实说明。

详见 [nat-traversal.md](nat-traversal.md) §8.3。

### 4.8 附件带来的额外风险

| 风险 | 说明 |
|---|---|
| **恶意文件内容** | 本项目**不做病毒扫描**。接收方执行文件是真实风险，而 E2EE 完全无法防护——内容正是发送方"合法"发出的 |
| **仅中继可达时的大文件** | 会显著推高中继带宽成本（见 [nat-traversal.md](nat-traversal.md) §9.2） |
| **附件大小泄露** | 传输量暴露大小，与消息长度泄露同类 |
| **文件名泄露** | 已防护（传输自动加密 + 本地 MK 加密） |
| **磁盘耗尽** | 已防护（接受前检查空间 + 大小上限） |

**UI 责任**：显示发送者的**信任状态**；打开文件交给操作系统；**绝不**根据对端声明的 MIME 自动打开或预览。

详见 [attachments.md](attachments.md) §13。

## 5. 密码学假设

本方案的安全性依赖于以下假设：

| 假设 | 若被打破 |
|---|---|
| X25519 的 CDH 困难性 | ECDH 派生的 SK 可被恢复 |
| ChaCha20-Poly1305 的 IND-CPA + INT-CTXT | 机密性与完整性失效 |
| HKDF-SHA256 是安全的 KDF | 派生密钥可预测 |
| SHA-256 抗碰撞 | `HandshakeHash` 无法防降级 |
| Ed25519 签名不可伪造 | 可冒充身份 |
| OpenPGP 实现（Go 库）无实现级漏洞 | 全盘失效 |
| Go 标准库与 x/crypto 的实现正确 | 同上 |

**依赖风险**：本项目依赖 `github.com/ProtonMail/go-crypto`。该库虽在维护，但**未经过与 libsignal 同等级别的独立审计**。若安全要求极高，需评估这一风险。

## 6. 安全要求（对实现的硬约束）

1. **禁止静默失败**：任何解密/认证明证失败都必须上报并可见。
2. **禁止使用 `math/rand` 生成任何密钥材料**，必须用 `crypto/rand`。
3. **禁止在日志中输出**：密钥、明文、口令、完整指纹（可输出指纹前缀供排查）。
4. **禁止在错误消息中回显**攻击者可控内容（防注入）。
5. **禁止默认信任**：未验证联系人不得静默升级为已验证。
6. **禁止 M1 宣称 PFS**（§4.2）。
7. **禁止复用 nonce**：任何密钥变更都必须伴随 seq 归零；任何 seq 重置都必须伴随密钥变更。这两者的绑定关系必须用**断言/测试**保障。
8. **禁止将 `Session.Seal`/`Open` 暴露给非预期的 goroutine**（见 [crypto-protocol.md](crypto-protocol.md) §11 的调用约束）。
9. **依赖必须锁定版本**并定期人工审查更新（尤其密码学依赖）。
10. **口令最小长度与强度检查**：argon2id 只能减缓暴力破解，不能弥补弱口令。

## 7. 残余风险清单

即使本方案全部正确实现，以下风险依然存在：

| 残余风险 | 严重度 | 可否缓解 |
|---|---|---|
| 用户未做带外指纹验证，被 MITM | 高 | 只能靠 UI 引导与用户教育 |
| 身份私钥泄露（M1）→ 历史全解 | 高 | 改用 M2 |
| 身份私钥泄露（M2）→ 未来消息仍可能被解 | 中 | 提高 ratchet 频率 |
| 消息长度泄露 | 中 | 填充（牺牲带宽），首期不做 |
| 在线状态与通信关系泄露 | 中 | 无法在局域网 P2P 下避免 |
| 端点被入侵 | 高 | 超出范围 |
| 无离线消息可能被用户误解为丢消息 | 中 | UI 明确禁用与提示 |
| 依赖库存在未知漏洞 | 中 | 版本锁定 + 关注公告 |
| 移动端后台不可用 | 中 | 明确产品预期 |
| **公网**：社交图泄露给会合/中继服务器 | 中 | 需匿名会合，超出范围 |
| **公网**：打洞失败率高时中继成本上升 | 中 | 中继配额 + 大文件拒绝 |
| **附件**：接收方执行恶意文件 | 高 | 无技术防护，靠 UI 警示与用户判断 |
| **附件**：中继传大文件导致成本激增 | 中 | 仅中继可达时拒绝大文件（需产品决策） |
| 改口令导致历史数据不可读 | — | ✅ 已由 MK 分层消除（[crypto-protocol.md](crypto-protocol.md) §10.2） |

## 8. 安全审查清单

发布前逐项确认（每项都应对应一个测试或有据可查的实现位置）：

- [ ] 所有密钥来自 `crypto/rand`
- [ ] `MaxFrame` 与变长字段边界校验完整，fuzz 测试通过
- [ ] nonce 与 seq 的绑定关系有测试保障，不存在重用路径
- [ ] 所有 AEAD 使用包含正确的 AAD
- [ ] KEM 载荷的四项校验（recipient_fp / 签名者 / ts 窗口 / sid 唯一）全部实现
- [ ] 重放窗口有单元测试覆盖边界（窗口内、窗口外、重复）
- [ ] 解密失败会上报且 UI 可见，无 `_ =` 忽略错误
- [ ] 日志中无密钥/明文/口令/完整指纹
- [ ] 未验证联系人状态在 UI 中持久可见
- [ ] M1/M2 的选择与文档描述一致
- [ ] 数据库中的消息正文为密文
- [ ] 依赖版本已锁定
- [ ] M2 的 PFS 属性有对应测试（泄漏 IK 后无法重建旧 SK）
- [ ] **改口令后历史数据仍可读**（MK 分层生效，有测试覆盖）
- [ ] 信令消息经验证签名后才采信候选地址（公网阶段）
- [ ] 附件分块：重排 / 截断 / 重放 / 篡改 四类用例全部覆盖
- [ ] 附件存盘路径不含对端提供的文件名（路径穿越防护）
- [ ] 附件不在应用内执行，且不按声明的 MIME 自动打开
- [ ] 接收附件前检查磁盘可用空间
